# CTA 回测与参数优化操作手册

本手册说明如何在 VeighNa Fusion 中完成一次可复核的 CTA 策略回测、查看结果并开展参数优化。回测用于验证历史区间内的策略逻辑、交易成本假设和风险特征，不代表未来收益，也不能替代模拟盘和实盘风控。

## 适用范围与前置条件

本手册适用于单合约 CTA 策略的图形化回测。开始前请确认以下事项：

- 已启动并登录 VeighNa Fusion；
- 待测策略已在策略列表中出现；如刚修改过策略文件，需执行一次策略重载；
- 本地数据库已经包含目标合约、目标周期和目标日期范围的历史数据；
- 已核对合约乘数、最小价格跳动、手续费、滑点和初始资金；
- 策略使用的历史数据类型与回测选择一致：K 线策略选择对应周期的 K 线数据，逐笔策略才选择 Tick 数据。

建议先在【功能】→【数据管理】中查询数据范围，并抽查数据是否有缺口、重复记录或明显异常价格。数据准备方法详见[历史数据管理](fusion_data.md)。

## 标准操作流程

一次回测应按“准备数据 → 配置参数 → 运行 → 复核明细 → 保存结论”的顺序完成。建议每次运行都保存策略版本、数据来源、回测区间和成本假设，避免以后无法复现结果。

### 1. 打开回测模块

在主界面选择【功能】→【CTA回测】，进入回测窗口。若策略下拉框中没有目标策略：

1. 检查策略文件是否放在系统扫描的策略目录中，且代码可以正常导入；
2. 点击【策略重载】；
3. 在日志中确认重载成功后，再从下拉框选择策略。

修改策略文件后，必须再次点击【策略重载】；否则回测仍会使用内存中旧版本的代码。

![](https://vnpy-doc.oss-cn-shanghai.aliyuncs.com/fusion/23.png)

### 2. 核对并准备历史数据

回测只会读取本地数据库中的历史数据。可在 CTA 回测界面下载数据，或在【数据管理】中导入已有数据；下载或导入后，数据会保存在本地，后续回测可重复使用。

请逐项核对：

- **本地代码**：必须包含交易所后缀，例如 `rb2406.SHFE`；
- **数据周期**：与策略实际处理的数据周期一致；
- **日期区间**：应覆盖回测开始日至结束日，以及策略初始化所需的预热区间；
- **连续性**：重点检查换月、停牌、节假日前后和交易时段切换处；
- **口径一致性**：不要混用复权与不复权、不同交易所或不同供应商口径的数据。

如果日志提示“历史数据不足，回测终止”，先返回数据管理模块确认该代码、周期和日期范围是否完全匹配，而不是先修改策略。

### 3. 填写回测参数

在左侧依次设置策略、合约、数据范围、交易成本和合约属性。各字段的填写原则如下：

| 项目 | 填写原则 | 常见错误 |
| --- | --- | --- |
| 交易策略 | 选择当前要验证的策略类 | 修改代码后未重载策略 |
| 本地代码 | 使用“合约代码.交易所”格式 | 漏写交易所后缀，或使用了错误合约 |
| K线周期 / 数据模式 | 与策略的事件处理逻辑和已准备数据一致 | 用日线数据验证依赖分钟入场的策略 |
| 开始、结束日期 | 留出初始化预热，并明确样本内或样本外区间 | 把全部数据都用于调参后再宣称验证有效 |
| 滑点 | 按**每手的价格跳动数量**估计实际成交偏离 | 设置为 0，或把金额直接填入 |
| 百分比手续费 | 按成交金额比例填写小数，例如万分之一填 `0.0001` | 填写 `0.01%`、`1` 等带百分号或错误数量级 |
| 固定手续费 | 若界面只提供百分比手续费，可换算为每手成本后计入滑点，或按实际可用字段设置 | 漏计开仓和平仓两侧成本 |
| 合约乘数 | 使用交易所/经纪商公布的每点金额对应乘数 | 将“一手保证金”误填为合约乘数 |
| 价格跳动 | 使用该合约最小报价变动单位 | 误用其他品种的跳动 |
| 回测资金 | 使用与拟实盘规模相近的初始权益 | 用过小资金得出不现实的仓位或收益率 |

交易成本会直接影响净利润、回撤和夏普比率。参数不确定时，可先做“基准 / 保守”两套成本假设，观察结论是否稳定。

![](https://vnpy-doc.oss-cn-shanghai.aliyuncs.com/fusion/24.png)

### 4. 设置策略参数并启动

点击【开始回测】后，系统会弹出策略参数窗口。这里填写的是策略的可配置参数，例如均线周期、突破阈值、止损幅度和下单手数；它们不同于上一节的交易成本和合约属性。

确认后点击【确定】启动。运行期间在日志区域检查：

- 数据加载的起止时间和数量是否符合预期；
- 策略是否完成初始化和启动；
- 是否出现异常、无成交、爆仓或历史数据不足的提示；
- 回测完成时间是否覆盖目标区间。

如需要中止或重跑，先记录当前配置；修改任一策略参数或基础参数后，都应重新运行一次完整回测，不能将不同运行的结果混合比较。

## 回测完成后的复核

回测完成后，先检查日志，再按“曲线—指标—逐笔明细”的顺序复核。不要只根据总收益率判断策略质量。

### 业绩图表

右侧图表通常包括：

- **账户净值**：观察权益增长是否平滑，是否高度依赖少数阶段；
- **净值回撤**：观察最大回撤的深度和持续时间；
- **每日盈亏**：判断收益是否集中、是否频繁出现极端亏损日；
- **盈亏分布**：了解日收益的离散程度和尾部风险。

![](https://vnpy-doc.oss-cn-shanghai.aliyuncs.com/fusion/54.png)

### 核心统计指标

优先一起阅读下列指标，而非单看某一项：

| 指标 | 用途 | 解读要点 |
| --- | --- | --- |
| 总收益率、年化收益 | 衡量回报规模 | 需与资金规模、交易期限和杠杆一起看 |
| 最大回撤、百分比最大回撤 | 衡量历史最坏权益回落 | 应与可承受风险和后续仓位管理相匹配 |
| 夏普比率 | 衡量单位波动下的收益 | 样本过短、收益集中时参考价值会下降 |
| 收益回撤比 | 比较收益与回撤的关系 | 更适合与同一成本口径的方案横向比较 |
| 总成交笔数、日均成交笔数 | 判断交易频率 | 过高可能对滑点和流动性极其敏感；过低则样本不足 |
| 总手续费、总滑点 | 量化摩擦成本 | 若成本占总盈亏比例过高，应优先检查策略容量 |

每日盈亏采用逐日盯市：净盈亏 = 持仓盈亏 + 交易盈亏 − 手续费 − 滑点。因此隔夜持仓的价格变化会计入当日结果。

### 检查委托、成交和 K 线图

使用左侧按钮打开【委托记录】、【成交记录】和【每日盈亏】，重点抽查开仓、平仓、止损和加减仓是否符合策略规则。表格右键可调整列宽或保存为 CSV，建议将关键回测的成交和日盈亏文件一并归档。

点击【K线图表】可将买卖点叠加在历史 K 线上，适合排查以下问题：

- 信号出现时点是否正确，是否使用了未来数据；
- 下单方向和开平仓方向是否符合预期；
- 成交价与策略下单价的差异是否符合设置的撮合和滑点假设；
- 大幅亏损是否集中在跳空、流动性不足或合约切换时段。

K 线图绘制在数据量较大时可能需要数十秒至数分钟。

## 参数优化操作

参数优化的目标是寻找**稳定的参数区间**，不是在历史数据上挑出唯一最高收益的组合。请先完成一组基准回测，并固定合约、区间、数据和成本设置后再优化。

### 1. 配置参数范围

点击【参数优化】，选择优化目标，并为每个待优化参数填写【开始】、【结束】和【步进】。例如参数范围 `10` 至 `20`、步进 `2`，会测试 `10、12、14、16、18、20` 六个取值。要固定某个参数时，将开始值和结束值设为同一个数。

组合总数等于各参数候选值数量的乘积。例如两个参数分别有 6 个和 5 个取值，将运行 30 次回测。首次优化建议只选择 1 至 3 个关键参数，并使用较粗的步进缩小范围。

![](https://vnpy-doc.oss-cn-shanghai.aliyuncs.com/fusion/25.png)

### 2. 选择算法并运行

- **多进程优化（穷举）**：遍历每一种参数组合；适合组合数量可控、需要完整结果表的场景。
- **遗传算法优化**：抽样、筛选和迭代地搜索参数空间；适合组合很多、需要更快找到候选区域的场景。结果是近似搜索结果，应以复跑验证。

优化期间会占用多个 CPU 核心。运行前请保存工作，并避免同时执行其他高负载任务。完成后点击【优化结果】查看排序，点击【保存】导出 CSV。

![](https://vnpy-doc.oss-cn-shanghai.aliyuncs.com/fusion/53.png)

### 3. 正确使用优化结果

1. 不直接采用排名第一的单点参数；优先选择周边多组参数表现都较稳定的区域。
2. 将历史数据划分为样本内和样本外：仅在样本内优化，再用未参与优化的样本外区间验证。
3. 用选出的候选参数重新进行一次普通回测，复核成交、成本和风险指标。
4. 在更保守的手续费和滑点假设下复跑；若结果明显失效，策略对交易摩擦过于敏感。
5. 通过模拟盘观察实时数据、真实交易时段和执行延迟的影响后，再考虑实盘。

## 常见问题排查

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| 提示“历史数据不足，回测终止” | 本地代码、周期、起止日期、数据库数据范围 | 导入或下载缺失数据；确认代码包含正确交易所后缀 |
| 策略列表中没有目标策略 | 策略文件路径、代码导入错误、是否刚改代码 | 查看日志定位导入异常，修复后点击【策略重载】 |
| 回测完成但没有成交 | 策略触发条件、预热数据、交易时段、参数数量级 | 在 K 线图和日志中定位首个应触发信号；不要把“无成交”直接当作系统故障 |
| 收益异常高或异常低 | 合约乘数、价格跳动、手续费、滑点、仓位 | 与合约规格逐项比对；抽查成交记录和日盈亏 |
| 修改策略后结果完全不变 | 是否执行了策略重载 | 点击【策略重载】并确认日志成功，再重新回测 |
| 优化运行过慢 | 参数数量、步进大小、回测区间、CPU 占用 | 缩小参数维度和区间；先粗搜、再局部细搜；或使用遗传算法 |
| 优化结果很好但换区间失效 | 过拟合、行情结构变化、成本假设乐观 | 使用样本外验证、滚动验证和更保守成本复测 |

## 回测归档清单

每个重要结论至少保存以下内容：

- 策略名称、代码版本或提交号；
- 合约、本地代码、数据来源、数据周期和回测起止日期；
- 初始资金、合约乘数、价格跳动、手续费和滑点；
- 策略参数与是否经过优化；
- 统计指标截图或导出结果、成交记录 CSV、每日盈亏 CSV；
- 对异常交易、最大回撤和样本外结果的简要说明。

回测与优化应被视为进入模拟盘前的验证步骤，而不是自动交易决策。完成数据准备后可参考[历史数据管理](fusion_data.md)，需要结合策略运行流程时可继续阅读[CTA策略](fusion_cta.md)。
